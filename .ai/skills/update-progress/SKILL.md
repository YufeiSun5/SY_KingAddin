# 更新开发进度

## 适用场景

- 刚完成一项编码任务（新功能、bug 修复、重构）
- 需要记录决策或发现供后续 Agent 参考
- 功能跟踪文档需要更新阶段状态

## 操作步骤

### 1. 更新 MEMORY.md

打开 `MEMORY.md`，按以下规则更新：

**「今日已完成」章节：**
- 追加一条简要描述：做了什么、影响了哪些文件/模块
- 如有遗留问题，在描述末尾注明
- 格式：`- 简要描述（影响：模块名/文件名）`

**「当前阶段」章节：**
- 如果项目阶段发生变化（如从"设计"进入"开发"），更新阶段描述
- 否则不动

**「后续建议事项」章节：**
- 已完成的建议项删除
- 新发现的待办补上

**「AI 工程化状态」章节：**
- 如果新增了 instructions、skills 或 docs，更新对应进度

**文件头部：**
- 更新 `> 最后更新：YYYY-MM-DD` 为当天日期

### 2. 更新功能跟踪文档（如适用）

如果工作涉及 `.ai/docs/` 下已有的功能跟踪文件：
- 找到对应任务行，更新「阶段」列和「日期」列
- 如果任务完成，标记 ✅ 和完成日期
- 如果产生了新的子任务，追加到对应章节

### 3. 评估是否需要新技能

回顾刚完成的工作：
- 这类操作以后还会重复吗？
- 操作步骤是否足够明确可以模板化？
- 如果两个条件都满足，在 `.ai/skills/` 下创建新技能

### 4. 评估是否需要更新 instructions

如果工作过程中确立了新的编码约定：
- 更新对应的 `.ai/instructions/*.md`
- 在对应章节末尾追加新条目

## 关键约束

- MEMORY.md 总长度控制在 100 行以内，历史内容归档到 `.ai/docs/changelog.md`
- 不要修改 AGENTS.md，除非项目定位或架构发生根本变化
- 记录要简洁客观，一条不超过两行
- 日期精确到天
