# AI 工作流程与文档维护规范

## 核心原则

AI Agent 不只是写代码的工具，也是项目文档的协作维护者。每次工作结束后，必须让后续 Agent（包括未来的自己）能快速理解当前状态。

## 文档更新时机

### MEMORY.md — 每次工作后必须更新

记录格式：

```markdown
## 今日已完成

- [日期] 简要描述做了什么
- [日期] 影响了哪些文件/模块
- [日期] 遗留了什么问题或待确认事项
```

更新规则：
- 「当前阶段」如果发生变化就更新
- 「今日已完成」追加新条目，不删除旧条目（除非按天归档）
- 「后续建议事项」完成的删掉，新发现的补上
- 保持文件总长度可控，超过 100 行时考虑将历史归档到 `.ai/docs/changelog.md`

### .ai/docs/ — 功能级跟踪

当工作涉及某个功能模块的开发时：
- 如果已有跟踪文件（如 `mysql-sync-feature.md`），更新对应任务的阶段和日期
- 如果是全新功能，创建新的跟踪文件，参照 `mysql-sync-feature.md` 的格式
- 文件名格式：`{feature-name}.md`

### .ai/instructions/ — 规范级文档

当工作内容确立了新的编码约定或修改了项目架构时：
- 更新对应的 instructions 文件（backend.md / frontend.md / http-api.md）
- 新增条目追加在对应章节末尾，不要打乱已有结构
- 如果是全新领域，可以新建 instructions 文件

### .ai/skills/ — 可复用操作模板

当你发现某类操作可以模板化时（至少做过两次相似操作），创建新技能：
- 目录名用 kebab-case：`.ai/skills/{skill-name}/SKILL.md`
- SKILL.md 必须包含 YAML frontmatter（name, description, argument-hint）
- 正文包含：适用场景、项目约定、操作步骤、关键约束

### AGENTS.md — 极少更新

只有以下情况才修改 AGENTS.md：
- 项目定位发生根本变化
- 新增了顶级模块（如 sync/）
- 技术栈发生重大变更

## 文档质量要求

- 保持简洁，每条记录不超过两行
- 用事实描述，不写主观评价（"代码质量不错" ✗ → "模块边界清晰" ✓）
- 时间标记精确到日期
- 如果不确定某件事是否值得记录，默认记录

## 典型工作闭环示例

```
1. 读 MEMORY.md → 了解当前进度
2. 读相关 instructions → 掌握编码规范
3. 读源码 → 理解现有实现
4. 编码实现 → 完成任务
5. 更新 MEMORY.md → 记录进度
6. 更新 .ai/docs → 如涉及功能模块
7. 考虑新技能 → 如发现可复用模式
```
